# Design Principles

1. Decide whether a Skill is needed before authoring.
2. One Skill should represent one coherent reusable job.
3. Split by responsibility/trigger/output/context/tool/security boundary, not by every sequential step.
4. Put deterministic operations in scripts/tools.
5. Put long knowledge in conditional references.
6. Keep assets as reusable inputs/examples, not hidden instructions.
7. Separate authoring from reviewing.
8. Evaluate routing, behavior, outcome, and regression.
9. Maintain both known-good and known-bad cases.
10. Treat GitHub as source of truth and use branch-first changes.
11. Treat public/private repository boundaries as security boundaries.
12. Derive public variants through explicit publication review rather than copying private Skills directly.
